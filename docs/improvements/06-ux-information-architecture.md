# User experience and information architecture

Ten findings, from reading the surfaces and the screenshots in `artifacts/`.

**Verified by hand:** `src/cad/engine.ts:890` really is
`new CadEngine(createShowcaseDocument())`, and `?intent=describe` is generated by
`navigation.ts:60` and read in **zero** places across `src/editor`,
`src/generation` and `src/App.tsx`.

The first two findings are the same shape and both sit on the primary
conversion path: **a landing CTA promises something the editor does not do.**

---

## 1. Make "Start a blank build" actually start blank

**Evidence:** `src/cad/engine.ts:890` — `export const cadEngine = new CadEngine(createShowcaseDocument())`. `src/cad/session.ts:80-127` resolves only to the newest saved project or `source: 'showcase'`; it never calls `createBlankDocument()`. Both `src/features/landing/Hero.tsx:75-84` ("Start a blank build") and `src/features/projects/ProjectsPage.tsx:8` ("Blank") link to plain `/editor`. Only `ProjectMenu`'s separate "New" button (`src/editor/ProjectMenu.tsx:226-236`) actually creates a blank document.
**Why it matters:** A first-time visitor clicking the primary CTA lands in a workbench already holding the 35-part Survey Rover showcase — contradicting the button's own label and the WelcomeGuide copy shown seconds later ("pick a part, then click in the viewport… each click drops another one"). **That showcase document is then autosaved as their real project.** A returning user gets an equally wrong result: "Blank" silently reopens whatever they last had open.
**Change:** Give `/editor` a signal (e.g. `?doc=blank`) that both CTAs pass, honoured at boot by constructing a blank document instead of running the restore chain.
**Effort:** M    **Risk:** Must not disturb autosave/restore for the far more common returning-user case.

## 2. Wire up the "Describe a build" deep link

**Evidence:** `src/features/landing/navigation.ts:59-60` returns `'/editor?intent=describe'`, used by `Hero.tsx:85-91` and `ProjectsPage.tsx:9`. Searching `App.tsx`, `useWorkbench.ts`, `Workbench.tsx` and all of `src/generation/*` for `intent` finds **zero readers**.
**Why it matters:** The second most prominent action on the landing page — and a starter card on `/projects` — promises to open the natural-language build flow and delivers the identical generic workbench, with the Generate panel unopened and (per finding 3) not even on screen without scrolling. The CTA's specific promise is silently dropped.
**Change:** Read `intent` at editor boot; when it is `describe`, expand the Generate dock section and focus its textarea.
**Effort:** M    **Risk:** Low; affects first-paint panel state only.

## 3. Surface the agent, generate and refine panels above the fold

**Evidence:** `src/editor/workbench/Workbench.tsx:363-414` renders Selection, Transform and Inspector — all open by default — *before* `<Slot id="panel-right">`, where `src/agent/contribution.tsx:21-23` ("Design partner", priority 120), `src/generation/contribution.tsx:24-31` ("Generate", 125) and `src/refinement/contribution.tsx:27-30` ("Refine", 130) attach, in one scrolling column (`src/styles.css:1064`). `artifacts/e2e-final.png` and `artifacts/workbench/state-dock-collapsed.png` show Selection/Transform/Inspector/Colour alone filling the entire dock height with nothing below visible.
**Why it matters:** The three panels that make this "agent-native" CAD are the last three items in a long scroll, below sections already tall enough to fill the dock on a 1600×1000 screen, with no cue that more exists.
**Change:** Give the right dock a section-jump strip, or move Agent/Generate/Refine into a tab row rather than appending to the same scroll; alternatively default Selection/Transform to collapsed.
**Effort:** M    **Risk:** Reshuffles a layout users may have customised — respect persisted `sections`/`layout` state.

## 4. Reconcile the three command-search surfaces

**Evidence:** `src/editor/workbench/shortcuts.ts:92-93` defines separate `project.command-palette` (⌘P, "Find and run any command by name") and `project.command-deck` (⌘/). `Toolbar.tsx:143-154` wires buttons for the Deck and the Shortcut Guide — **nothing opens the palette**. `ShortcutGuide.tsx:11-27` is a hardcoded list, not generated from `shortcuts.ts`, mentioning ⌘K and ⌘/ but never ⌘P.
**Why it matters:** Two similarly-named "find a command" affordances exist, and the one literally named for command discovery — which also holds the rebindable-keys editor — is absent from the toolbar, the help screen and the other command surface. It is reachable only by already knowing to press ⌘P.
**Change:** Merge the palette's run/keys functions into the Deck under one name, or add it to the toolbar and generate `ShortcutGuide` from `shortcuts.ts` so the two cannot drift again.
**Effort:** M    **Risk:** Merging touches two independently tested components; generating the guide risks losing its hand-grouped presentation unless groups are modelled too.

## 5. Add a way out of the editor

**Evidence:** `src/editor/workbench/TopBar.tsx:19-22` — the brand lockup is a plain `<div>` with no `href` or `onClick`. Searching every `src/editor/**/*.tsx` for `href="/"`, `navigate(` or `<a` returns **zero matches**. `src/platform/routes.ts:102-104` deliberately excludes `editor` from the persistent frame that carries `PRIMARY_NAV`.
**Why it matters:** Once inside `/editor` — the most-used surface — there is no in-app control to reach Explore, Gallery, Projects or the landing page. Only browser Back or hand-editing the URL works, which is invisible to anyone who arrived from a shared link or a fresh tab.
**Change:** Make the brand lockup a link or menu into `PRIMARY_NAV`, consistent with how `ProjectMenu` already occupies that corner.
**Effort:** S    **Risk:** Must not intercept editor shortcuts or steal focus from the viewport.

## 6. Confirm before deleting a local project

**Evidence:** Three surfaces, three different safety postures for the same irreversible action. `src/editor/ProjectMenu.tsx:258-266` — a trash icon calling `session.deleteProject(...)` **with no confirmation**, in a 36px button flush against the full-row open target (`styles.css:207-215`). `src/features/projects/ProjectsPage.tsx:180-196` — "Delete" flips in place to "Confirm delete" **at the same screen position**, no cancel, no warning. `src/cloud/ProjectsPanel.tsx:509-529` — the only one with a real dialog: "This cannot be undone from here", "Delete permanently" / "Keep it".
**Why it matters:** The two most-used surfaces let a single click, or two clicks on the same pixel, permanently destroy a saved build and its history with no warning.
**Change:** Reuse the cloud panel's confirm-with-warning pattern in both other surfaces.
**Effort:** S    **Risk:** None functional; carry over the existing focus and keyboard handling.

## 7. Stop naming the generic agent connection "Codex"

**Evidence:** `src/editor/workbench/TopBar.tsx:47,50` — `className="codex-state"`, text `'Codex connected'`. `src/editor/workbench/AutonomySwitch.tsx:6` — `aria-label="Codex autonomy mode"`. But `src/webmcp/adapter.ts:656-658` reports `native: Boolean(document.modelContext)` — the **vendor-neutral WebMCP browser API**, nothing specific to any one product.
**Why it matters:** The product's own copy is carefully agent-neutral ("You decide what the agent may do", "agent-native brick CAD"), yet the live status pill and a screen-reader label both name a specific third-party product regardless of which agent is actually attached. Confusing at best, factually wrong at worst.
**Change:** Rename the class, visible copy and aria-label to something generic — "Agent connected" / "Native tools connected".
**Effort:** S    **Risk:** Cosmetic; check for tests or selectors keyed on `.codex-state`.

## 8. Add friction before granting unsupervised Build access

**Evidence:** `src/editor/workbench/AutonomySwitch.tsx:4-17` — Inspect, Propose and Build are one `onClick` each, identical interaction cost. `src/editor/WelcomeGuide.tsx:58-61` explains Build ("commit directly") once, at first run.
**Why it matters:** Escalating from read-only Inspect to unsupervised Build — where an attached agent commits edits without staging a reviewable ghost — takes one click, with no reminder of what is being granted at the moment it matters (when an agent is actually connected), rather than at onboarding possibly days earlier.
**Change:** When switching to Build while a native/MCP session is active, show a one-time-per-session confirmation naming what the mode allows. Leave Inspect↔Propose frictionless.
**Effort:** S    **Risk:** Must not add friction to the far more frequent toggle.

## 9. Cut the repeated revision and selection chrome crowding the viewport

**Evidence:** `src/editor/workbench/ViewportStage.tsx:101-111` stacks a breadcrumb ("ASSEMBLY / MASTER MODEL"), an eyebrow ("CATALOG-BACKED ASSEMBLY / REV 26"), a display heading ("SURVEY ROVER // R26") and a selection line in one corner, while `TopBar.tsx:45` separately shows "Saved r26" and the status bar repeats the selection state again. `artifacts/e2e-final.png` shows all of it at once over the model.
**Why it matters:** The same two facts — which revision is open, what is selected — are stated three to four times across the one region that already gets only about half the screen for the actual 3D model.
**Change:** Keep one instance of revision (TopBar) and one of selection (status bar or inspector header); drop or compact the overlay duplicates.
**Effort:** S    **Risk:** Confirm the breadcrumb carries no click target (subassembly navigation) before removing rather than relocating it.

## 10. Make builder notes actionable where they are shown

**Evidence:** `src/editor/workbench/TimelinePanel.tsx:138-141` — `.timeline-note` is a plain non-interactive `<div>` showing only the first open note, with no click handler and no count of others. The only capability that resolves one, `respond_to_note` (`src/cad/capabilities.ts:906-913`), needs a `noteId` that is never rendered in the human UI and is invoked only from `CommandDeck.tsx`.
**Why it matters:** A note like "Cockpit geometry is final. Build around it." sits pinned in the corner of the workbench in nearly every screenshot, reading as an actionable to-do, with no way to open, reply to or resolve it — and no indication when more are open.
**Change:** Make the note a button that opens it inline (full text, reply, resolve) or routes into the Command Deck with `respond_to_note` pre-filled; show a count when several are open.
**Effort:** M    **Risk:** Needs a small interactive surface; scope it to reuse the existing Command Deck detail pane.
